## 2026-09-14: BaseMachine Architectural Review — Unified Contract

### BaseMachine Refactor

- **Author**: KAFE Engineering System
- **Summary**: Comprehensive architectural review and refactor of `BaseMachine` and all child classes in KafeMACHINE. Established a unified contract with flexible `fit()` signatures, centralized fitted state, consistent DataFrame support via `_unwrap_data()`, centralized dimension validation via `_validate_matrix_shape()`, and eliminated metric duplication in `score()` methods.
- **Reason**: The original `BaseMachine` had multiple architectural inconsistencies: `fit()` signatures varied without documentation, DataFrame support was inconsistent, dimension validation was duplicated across classes, `score()` reimplemented existing metrics, and `fit_transform()` was broken for encoders.
- **Decisions Made**:
  1. Flexible `fit()` contract — semantic, not syntactic (each category defines its own signature)
  2. Centralized `_is_fitted` in BaseMachine.fit()
  3. DataFrame support where it makes sense (transformers + models, not LabelEncoder)
  4. `_unwrap_data()` returns `(matrix, columns, is_dataframe)` — documented
  5. Centralized `_validate_matrix_shape()` in BaseMachine
  6. `score()` reuses existing metrics from `metrics.py`
  7. Removed `fit_transform()` from BaseMachine (each transformer implements its own)
  8. `predict_proba()` not in BaseMachine (only probabilistic classifiers)
- **Impacted Modules**: `BaseMachine.py`, `LinearRegression.py`, `LogisticRegression.py`, `KNN.py`, `DecisionTree.py`, `KMeans.py`, `StandardScaler.py`, `MinMaxScaler.py`, `PCA.py`, `SimpleImputer.py`, `LabelEncoder.py`
- **Related ADRs**: ADR-0007
- **Validation Performed**: `pytest tests/ -q` — 344 passed

### score() Optional Metric Support

- **Author**: KAFE Engineering System
- **Summary**: Updated `score()` in BaseMachine and all model classes to accept an optional `metric` parameter. Users can now pass any metric function from `metrics.py` (e.g., `f1_score`, `precision_score`). ### Preprocessing Improvements — Validation and Error Handling

- **Author**: KAFE Engineering System
- **Summary**: Improved validation and error handling in preprocessing components. PCA now validates `n_components <= n_features` in `fit()`. OneHotEncoder gained `handle_unknown` parameter ("error" by default) and strict validation in `inverse_transform`. SimpleImputer validates numeric type for "mean"/"median" strategies.
- **Reason**: Prevent silent failures and confusing errors. Users should get clear, actionable error messages when providing invalid input.
- **Decisions Made**:
  1. PCA: validate `n_components <= n_features` in `fit()`
  2. OneHotEncoder: `handle_unknown="error"` default — user must explicitly choose to ignore unknowns
  3. OneHotEncoder `inverse_transform`: strict validation, no silent fallback
  4. SimpleImputer: validate numeric type for "mean"/"median" strategies
  5. Preprocessors do NOT use `_validate_matrix_shape()` — dimension validation in `transform()` is sufficient
- **Impacted Modules**: `PCA.py`, `OneHotEncoder.py`, `SimpleImputer.py`
- **Related ADRs**: ADR-0007 (sections 9-13 added)
- **Validation Performed**: `pytest tests/ -q` — 344 passed

## 2026-09-14: Model Validation Improvements

### Model Validation Improvements

- **Author**: KAFE Engineering System
- **Summary**: Added dimension validation in `predict()` for all 5 models (LinearRegression, LogisticRegression, KNN, DecisionTreeClassifier, KMeans). Added `len(X) == len(y)` validation in `fit()` for LogisticRegression, KNN, and DecisionTreeClassifier. Added hyperparameter validation (`learning_rate > 0`, `max_iter > 0`) in LogisticRegression `__init__()`.
- **Reason**: Prevent silent failures. `zip()` in KNN could silently truncate dimensions. Missing `len(X) == len(y)` caused cryptic IndexErrors. Invalid hyperparameters produced broken models without warning.
- **Decisions Made**:
  1. All models validate feature dimensions in `predict()` against fitted state
  2. All supervised models validate `len(X) == len(y)` in `fit()`
  3. LogisticRegression validates `learning_rate > 0` and `max_iter > 0` in `__init__()`
- **Impacted Modules**: `LinearRegression.py`, `LogisticRegression.py`, `KNN.py`, `DecisionTree.py`, `KMeans.py`
- **Related ADRs**: ADR-0007 (sections 14-16 added)
- **Validation Performed**: `pytest tests/ -q` — 354 passed
