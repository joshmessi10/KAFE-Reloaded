# Command Set Completion and Mandatory Invocation Enforcement

- **Date**: 2026-08-03
- **Author**: Engineering System
- **Summary**: Completed the command set and enforced mandatory invocation. Created `/open-work` (`.opencode/commands/open-work.md`) as the start-of-work lifecycle command: it confirms no other work item is in progress, selects the item from the backlog/roadmap, initializes `.opencode/progress/current.md` and `.opencode/memory/active-work.md`, marks the backlog item, and flags when `/impact` is mandatory. Created `.opencode/commands/README.md` documenting the 8 commands in lifecycle order (`/init` → `/resume` → `/open-work` → `/impact` → `/adr` → `/benchmark` → `/dod` → `/close`) with a Mandatory Invocation matrix (command, when it must run, where it is enforced). Closed the enforcement gaps: `/impact` is now step 1 of `create-library/SKILL.md` (a new library is a public API + dispatch change); `/close` requires `/dod` for the active work item before closing (Definition of Done gate in `close.md` and `engineering.md` Session Closure Process, fulfilling the ADR-0004 follow-up); session start explicitly runs `/init` + `/resume` (OPENCODE.md Startup Procedure and AGENTS.md "If you are…" table with new rows for starting a session, opening a work item, changing public APIs/refactoring the core, and completing a task); `/benchmark` is referenced in the benchmarks README; `/init` check 9 and the ADR-0001 command list include `/open-work`.
- **Reason**: Commands are the executable parts of the engineering process; they only work if they are actually called where they are mandatory. The set now covers the full session lifecycle and every documented trigger is auditable in the repository.
