# Octubre 2026

## Bounded KafeGESHA CI training (2026-10-19)

The 1000-epoch XOR, AND, and OR teaching fixtures could delay CI for several minutes each while their captured output hid progress. A two-epoch CLI revision did not learn the truth tables, so the fixtures now use Adam and 25, 15, and 40 epochs respectively. Each fixture must correctly classify all four inputs and match its exact output snapshot; separate short backend tests verify loss reduction and valid probabilities. Four previously excluded RNN, autoencoder, and circle convergence examples remain skipped. Existing gradient and layer tests remain active. KafeGESHA CLI fixtures have a 120-second process limit.

## Safe integration reconstruction (2026-10-19)

The previous integration branch replaced current `main` modules and broke test collection. A new isolated branch based on `main` now ports the feature additions while preserving the existing `geshaDeep` API. The redesigned Gesha backend is exposed as `geshaV2` (ADR-0013), and Kaggle, NUMK, HF, and MACHINE additions are adapted to current module names. The original feature checkout remains at `b6a2260`. Local Ruff, basedpyright, suppression-policy, strict documentation build, and focused backend tests pass. The full test suite is still pending. The user authorized Spanish educational content; ADR-0014 and a reviewed codespell vocabulary allow that content while preserving spelling checks. The branch has not been published.

## KafeKAGGLE v2 — cliente `kagglehub` (datasets públicos sin credenciales)

La validación en vivo de KafeKAGGLE demostró que el gate de credenciales de
ADR-0012 bloqueaba datasets públicos que la API sirve de forma anónima (GET
anónimo → HTTP 200; `kagglehub.dataset_download('uciml/iris')` sin ninguna
credencial → descarga y extracción correctas). Se reemplazó el cliente
`kaggle`/`KaggleApi` por **`kagglehub`** (cliente oficial moderno, el mismo
de Google Colab, que además soporta las mismas fuentes de credenciales:
`kaggle.json`, env vars y secrets de Colab).

Cambios (ADR-0013, supresión parcial de ADR-0012): descarga anónima para
públicos — `_check_credentials()` pre-gate → predicado

descarga falla sin credenciales (privados); `_download_dataset(dataset_name)`
retorna el directorio extraído (caché persistente `~/.cache/kagglehub`, sin
`TemporaryDirectory` ni `zipfile`); `_extract_table` recorre el directorio
 recursivamente; auto-install `_require_kagglehub()`. API pública KAFE y
semántica de `split` intactas; también desaparece el texto de ayuda en
inglés que `kaggle 2.2.4` imprimía al importar sin credenciales.

Tests: los 5 fixtures `.kf` no cambiaron; los unit tests pasaron de 27 a 35
(nuevos: walk de subdirectorios, predicado de credenciales, hint de error,
stdout limpio con `capsys`, restauración de streams de logging del cliente).
Benchmark re-ejecutado (S5 ahora directorio en
lugar de ZIP) y `records.md` actualizado. Docs, concept record,

## KafeKAGGLE — API genérica de ingesta de imágenes (2026-10-13, ADR-0018)

Se reemplazó `load_cifar10` —cargador experimental específico de CIFAR-10, sin
tests ni documentación y acoplado a KafeMACHINE— por una **API genérica de
imágenes** construida sobre `kagglehub` (ADR-0013) y desacoplada de cualquier
dataset. Tres funciones: `load_image` (una imagen `[C][H][W]`),
`load_images` (`List[[C][H][W]]`, orden determinista por ruta relativa) y
`load_image_dataset` (contenedor indexable `MACHINE` con `[0]=X`, `[1]=y`,
etiquetas codificadas `0..N-1` en orden alfabético). Los píxeles se normalizan
`p/255` a `[0,1]` con layout CHW que consumen las capas Conv2D de GESHA
(ADR-0011); `color_mode` acepta `"rgb"` (3 canales) y `"gray"`/`"grayscale"`
(1 canal); `limit` acota cuántas imágenes se cargan.

Dependencias opcionales con auto-instalación diferida: `Pillow` (decodificación
PNG/JPEG/BMP y redimensionado) y `py7zr` (extracción de `.7z` anidados; `.zip`
usa la stdlib `zipfile`). El descubrimiento es recursivo (`.png/.jpg/.jpeg/.bmp`,
ignora `__MACOSX`/dotfiles) y la extracción valida cada entrada contra *path
traversal*. La descarga y las dependencias quedan aisladas en funciones
sustituibles, de modo que toda la batería de pruebas de imágenes corre sin red
ni `pip`.

La división train/test **no** la realiza KafeKAGGLE: queda en
`machine.stratified_train_test_split`. Para permitirlo, la decisión **A1** relajó
el tipo del parámetro `X` de `train_test_split` y `stratified_train_test_split`
de KafeMACHINE de `matriz_numeros_t` a `lista_cualquiera_t` (de
`src/TypeUtils.py`), aceptando tensores de imagen 4D `[N,C,H,W]` de forma
retrocompatible (`y` permanece `vector_numeros_t`). `load_image_dataset`
devuelve un contenedor `ImageDataset` (subclase de `KafeMACHINE.BaseMachine`,
tipo KAFE `MACHINE`) porque KAFE rechaza enlazar una lista heterogénea `[X, y]`.

`src/Ejemplo.kf` migró a `load_image_dataset` + `machine.stratified_train_test_split`
para entrenar una CNN Mini sobre CIFAR-10. La suite pasó a **628 passed,
2 skipped** (baseline previa 577/1; +51 pruebas con las 64 pruebas backend de
imágenes). Acompañan a la decisión el ADR-0018, el concept record
`kaggle-image-ingestion.md`, `docs/bibliotecas/kaggle.md`,
`knowledge/libraries.md`, el benchmark offline de 5 escenarios
(`kafekaggle_images.py` + `records.md`) y el roadmap.

## KafeKAGGLE: ingesta robusta de datasets de imágenes por carpetas (ADR-0019)

**Contexto**: `src/Ejemplo.kf` (CIFAR-10) volcaba miles de rutas a stdout en vez
de entrenar. Causa: `load_image_dataset(..., "trainLabels.csv", ...)` sobre
`ayush1220/cifar10`, que no trae CSV de etiquetas (las clases son carpetas:
`train/<clase>/NNNN.png`) y cuyos basenames se repiten entre carpetas. El mensaje
de error interpolaba ~60000 rutas y el proceso terminaba con código 0.

**Cambio**: nueva función `load_image_folder_dataset(dataset_name, height=32,
width=32, color_mode="rgb", limit=0, split="train")`: la etiqueta es el nombre de
la carpeta padre; `split` filtra por subdirectorio ancestro (`""` = todas); se
aplica una mezcla determinista (semilla 42) antes de `limit`; etiquetas
codificadas `0..N-1` en orden alfabético. Además: `_formatear_lista` trunca las
listas en los mensajes de error y `_download_dataset` verifica que la descarga
produzca archivos. `src/Ejemplo.kf` migrado a la nueva API.

**Archivos**: `src/lib/KafeKaggle/funciones.py`, `src/lib/KafeKaggle/__init__.py`,
`src/Ejemplo.kf`, `tests/test_KafeKaggle_backend.py` (80 tests),
`tests/KafeKaggle/kaggle_load_image_folder_dataset.kf.example`,
`docs/bibliotecas/kaggle.md`, `.opencode/knowledge/libraries.md`,
`.opencode/knowledge/concepts/kaggle-image-ingestion.md`.

**Validación**: `pytest tests/ -q` → 645 passed, 2 skipped. E2E contra la caché
real de CIFAR-10 (60000 imágenes; 50000 train / 10000 test; `X=[40,3,32,32]` en
`[0,1]`). Benchmark offline de 5 escenarios en
`.opencode/benchmarks/kafekaggle_images_folders.py` (registrado en
`.opencode/benchmarks/records.md`).

**Decisión**: ADR-0019.

## Optimización del entrenamiento de CNN en GESHA/NUMK (2026-10-17, ADR-0020)

**Contexto**: `src/Ejemplo.kf` (CNN Mini CIFAR-10: Conv2D(8) → MaxPooling2D(2x2)
→ Conv2D(16) → GlobalAveragePooling2D → Dense(10, softmax), 4000 imágenes × 5
épocas, batch 16) tardaba ≈2 h 19 min. No había ningún fallo: era coste de
Python puro más un defecto real de trabajo redundante.

**Cambio** (cinco optimizaciones bit-idénticas):
* **F1** — `src/lib/KafeNUMK/funciones.py`: `conv2d_chw_backward` ejecutaba una
  convolución FORWARD COMPLETA dentro del backward sólo para calcular la forma
  esperada (~30 % del entrenamiento). La forma se calcula ahora aritméticamente
  y `expected` es una **tupla** `(filters, out_h, out_w)` (crítico:
  `numk.shape()` devuelve tupla; con lista, `!=` habría sido siempre verdadero).
  Validaciones y mensajes de error preservados en el mismo orden.
* **F5** — `funciones.py`: en `conv2d_chw` y `conv2d_chw_backward`, hoisting de
  filas/kernels y estrechamiento del rango válido de `kx` (`kx_start`/`kx_end`
  por celda de salida), eliminando el `if 0 <= ix < width` por iteración
  interna. Se descartó el pre-padding con ceros por riesgo de diferencias en el
  cero con signo.
* **F2** — `src/lib/KafeGESHA/models.py`: la lista deduplicada de parámetros
  (`batch_parameters`) se calcula UNA vez tras el primer `forward` (capas lazy)
  y se reutiliza, en lugar de reconstruirse por muestra (L151, L163-165).
* **F3** — `models.py`: acumulación de gradientes del minibatch in-place con el
  helper `_acumular_en` (L48-55, L176-184), en lugar de crear un tensor nuevo
  por muestra con `numk.tensor` + `map_elements`.
* **F4** — `src/lib/KafeGESHA/optimizers/adam.py`: helper `_adam_actualizar`
  (L7-19) con UNA pasada recursiva (momentos y parámetros in-place) y las
  correcciones de sesgo `1-beta1**t` / `1-beta2**t` precalculadas una vez por
  `step` (L34-35), en lugar de recalcularlas por escalar con 3 pasadas
  `map_elements`.
* **F6** (one-hot de `SparseCategoricalCrossEntropy`) DESCARTADO por impacto
  despreciable (<0.01 %, arrays de 10 clases) frente al riesgo de tocar la API
  compartida de las pérdidas.

**Validación**: requisito duro de resultados **bit-idénticos** (mismo orden de
acumulación en coma flotante). Verificado: **288/288 combinaciones
bit-idénticas** (igualdad exacta `==` sin tolerancias) entre implementaciones
naive y optimizadas para forward y backward (`dx`, `dw`, `db`), y **9/9
contratos de error preservados** (`.opencode/tmp/conv_equiv_results.md`).
Benchmark de 5 escenarios, mediana de 5 repeticiones con `perf_counter`
(`.opencode/benchmarks/gesha_cnn_optimization_results.md`): conv1 fwd 45.123 →
28.993 ms (1.56×); conv1 bwd 114.703 → 49.369 ms (2.32×); conv2 fwd 57.459 →
39.261 ms (1.46×); conv2 bwd 145.268 → 63.295 ms (2.30×); `fit` end-to-end
521.949 → 384.789 ms/muestra (1.36×; el "antes" de S5 procede de una sesión
anterior, los S1-S4 comparan naive vs optimizada en la misma sesión). Suite
completa `pytest tests/ -q` tras F1-F5: **645 passed, 2 skipped** (idéntico al
baseline; también 645/2 tras aplicar sólo F2/F3/F4).

**Desviaciones operativas**: (1) el subagente Architect no tiene herramienta de
escritura en su runtime (sólo read/glob/grep) pese a `edit: allow` en
`.opencode/agents/architect.md` y `opencode.json`, y devolvió `blocked` al
intentar escribir el impact analysis; (2) el subagente Builder produjo un falso
`done` en un despacho multi-entrega (declaró escrito
`.opencode/tmp/builder-conv-optimization.md` y editado `funciones.py` cuando
ninguno de los dos existía), detectado releyendo disco y resuelto re-despachando
con alcance mínimo; (3) el placeholder `"model": "<tu-modelo>"` sigue sin
sustituirse en `opencode.json` (architect/historian).

**Archivos**: `src/lib/KafeNUMK/funciones.py`,
`src/lib/KafeGESHA/models.py`, `src/lib/KafeGESHA/optimizers/adam.py`,
`.opencode/tmp/conv_equiv.py`, `.opencode/tmp/conv_equiv_results.md`,
`.opencode/benchmarks/gesha_cnn_optimization.py`,
`.opencode/benchmarks/gesha_cnn_optimization_results.md`.

**Decisión**: ADR-0020 (`rendimiento: eliminación de trabajo redundante en la
convolución y el bucle de entrenamiento`); impact analysis en
`.opencode/progress/impact-cnn-performance.md`.

## Validación E2E de RNN con KafeKaggle: series temporales y texto (2026-10-18)

**Contexto**: `src/Ejemplo.kf` cubría el camino CNN+imágenes, pero la cadena RNN de GESHA no estaba ejercitada de punta a punta desde KAFE: `create_rnn`/`embedding` solo tenían unit tests Python. Dos datasets reales de Kaggle expusieron los bloqueantes: (a) KafeKaggle solo admitía CSV con coma y encabezado (`_select_file` rechazaba `.txt`), y el dataset de sentimiento (`marklvl/sentiment-labelled-sentences-data-set`) es `.txt` con TAB y sin encabezado; (b) no existía tokenizador texto→índices para la capa `Embedding` (exige `List[INT]`).

**Cambio**: (1) `kaggle.load_text_dataset(dataset_name, file_name="", delimiter="\t", text_column=0, label_column=1, limit=0)` → PARDOS con columnas `text`/`label`, apoyada en `_leer_filas`, `_parse_text_labels` y `_select_file_texto` (acepta `.txt`/`.tsv`/`.csv`); la API CSV anterior quedó intacta. (2) Nuevo transformer `machine.tokenizer(num_words=0, oov_token="")` (`src/lib/KafeMACHINE/preprocessing/Tokenizer.py`, hereda `BaseMachine`): tokenización por `re` (minúsculas + no-alfanuméricos), vocabulario determinista por (-frecuencia, primera aparición), índice 0 reservado, OOV opcional en índice 1, `num_words` como acotamiento. (3) `src/EjemploRNN1.kf`: temperaturas mínimas de Melbourne (`paulbrabban/daily-minimum-temperatures-in-melbourne`), ventanas deslizantes [7,1] construidas con `while`, split CRONOLÓGICO 80/20 (sin barajar: data leakage temporal), min-max con estadísticas del train, `SimpleRNN(16,tanh)+Dense(1,linear)`, adam/mse lr 0.01, 15 épocas → MAE 2.71 °C. (4) `src/EjemploRNN2.kf`: sentimiento Yelp (`yelp_labelled.txt`), split estratificado, tokenizer fit SOLO sobre train (evita fuga de vocabulario), `Embedding+SimpleRNN(8)+Dense(1,sigmoid)`, adam/bce, 8 épocas → accuracy test 0.5823, matriz `[[18,17],[16,28]]`, y 3 frases nuevas clasificadas (2/3 correctas); la cabecera documenta honestamente el overfitting con SimpleRNN pura y ~284 frases. (5) Limitación conocida documentada: `Model.predict` confunde muestra única con lote en secuencias → los ejemplos predicen siempre por lote; fix como follow-up.

**Archivos**: `src/lib/KafeKaggle/funciones.py`, `src/lib/KafeKaggle/__init__.py`, `src/lib/KafeMACHINE/preprocessing/Tokenizer.py`, `src/lib/KafeMACHINE/funciones.py`, `src/EjemploRNN1.kf`, `src/EjemploRNN2.kf`, `tests/test_KafeKaggle_backend.py`, `tests/test_KafeMACHINE.py`, fixtures `tests/KafeMACHINE/preprocessing/test_tokenizer_*.{kf,expec}` y `test_tok_*.{error.kf,error.expec}`, `tests/KafeGESHA/rnn_sintetico.kf`, `tests/KafeGESHA/rnn_embedding_sintetico.kf`, `tests/KafeKaggle/kaggle_load_text_dataset.kf.example`, `.opencode/benchmarks/rnn_e2e.py` + `rnn_e2e_results.md`, `.opencode/progress/impact-rnn-e2e.md`, `.opencode/adr/decisions.md` (ADR-0021), `docs/bibliotecas/kaggle.md`, `docs/bibliotecas/machine.md`.

**Validación**: `pytest tests/ -q` → **691 passed, 2 skipped** (baseline 645/2 antes del feature).
