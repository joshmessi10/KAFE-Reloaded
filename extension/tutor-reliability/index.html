    Maintaining KAFE Tutor code guidance¶

    Extension 2.3.0 bundles KAFE fundamentals, reviewed MACHINE/GESHA API contracts, canonical library documentation, tutorial text and selected complete repository fixtures. English and Spanish requests use the same version-matched sources. The references and bundled knowledge tool lookup work before executable runtime or managed-pack setup, including message-only Restricted Mode. A bare greeting receives fundamentals without incidental library/example search; the teaching policy keeps it brief.

    The intended top-level inventory contains 58 MACHINE functions, 56 GESHA wrappers and five activation aliases. Reviewed receiver contracts also describe methods, properties, argument/shape constraints and supported, limited, experimental, deprecated or unsupported behavior. These are 512 reference records: 420 MACHINE and 92 GESHA, rather than 512 independent learner capabilities. All 58 MACHINE functions, 55 usable GESHA wrappers and five activation aliases have successful direct KAFE evidence. The remaining GESHA wrapper, l1_l2_regularizer, has negative evidence for its unavailable GESHA binding. Backend-only hooks and known limits are documented without changing the runtime.

    Curated reference/machine-api.json and reference/gesha-api.json feed generated src/tutor/libraryReferences.json. Contracts use actual positional KAFE call forms, return types and reviewed evidence. Source-derived inventory and receiver-member checks reject missing records. An explicit reviewed source fingerprint and runtime revision require renewed review when semantics change; ordinary regeneration cannot advance that attestation. Contract, corpus, evidence and content hashes detect drift. The current and actual pinned interpreter fingerprints must match. The pinned revision must exist locally; CI fetches full history. A checkout-only test does not establish pinned-runtime compatibility.

    The shared reference/knowledge-corpus.json selects canonical documentation/grammar and Markdown/KAFE tutorials from docs/ejemplos, mapped to examples/tutorials. SVGs are excluded explicitly. Bundled generation, development packs and future managed builds use this selection; safe paths, exact identities and 512-file / 256 KiB-per-file / 8 MiB-total limits remain. The published runtime 0.3.0 assets stay unchanged. Updated managed packs require a future committed source revision and versioned release; historical revisions without a corpus manifest retain the six required legacy sections. Current bundled MACHINE/GESHA contracts and tutorials take precedence over old managed library narratives.

    Exact qualified names, reviewed API aliases and normalized case, accents, camelCase and underscores support bilingual retrieval. Fundamentals remain separate. Library selection admits at most three complete units and 8 KiB; library material and fixtures together share 12 KiB. Each admitted library/example unit is at most 6 KiB. Bundled tool lookup admits at most five units and 12 KiB. Managed/development search retains five passages, two per file and 2,000 characters per passage. Headings, signatures, tables, fences and standalone source units remain intact; oversized or incomplete fenced units are omitted instead of clipped into runnable-looking code. Generated omission records retain those limits. Full library coverage does not require sending the entire corpus on every request.

    src/tutor/kafeReferences.json contains reviewed .kf, .expec and optional .in pairs from reference/catalogue.json, including labelled expected-error fixtures. Unreviewed fixtures remain listed as omitted; missing expectations fail generation. Fixture examples retain complete code/input/expected results, at most three examples within the remaining shared reference budget. Licensing is preserved in packaged references. Bundled provenance never impersonates a ready managed/development pack, a learner file or a host-observed execution. Matching reference identities do not prove an installed runtime, a new program or a model answer correct.

    Contributor workflow¶

    Use Node 24 LTS. Install extension dependencies inside kafe-vscode before launching the Development Host:

    npm ci
npm audit --audit-level=low

    For each language or library change:

    1. Review actual pinned wrapper argument checks, returned objects and supported DSL behavior. Update the relevant API JSON, source-symbol mappings, documentation, aliases and valid/negative KAFE evidence. Keep unsupported paths explicit; incidental Python imports and default arguments are not public DSL APIs. If source identity changes, coordinate the runtime/version pin and renew the curated review attestation after review rather than editing hashes to bypass a failure.
    2. Keep pure deterministic teaching examples in reference/catalogue.json. Declare filesystem examples and their reviewed local assets separately in the API file's isolatedFixtures; the weights workflow is isolated evidence, not a pure teaching fixture. Long training, network downloads and credentials require separately identified integration checks. Do not execute generated model code for reference verification.
    3. Update reference/essentials.md only for core syntax/execution changes. Add documentation/tutorial inputs through the shared corpus manifest; presentation assets do not enter reference text.
    4. Run npm run references:build, npm run references:check and npm run test:unit from kafe-vscode. These commands cover fundamentals/fixtures and library contracts/corpus/evidence. Freshness, completeness, bilingual retrieval, unavailable APIs, intact-unit budgets and packaging are distinct checks. Cross-language corpus tests need Python; KAFE_PYTHON can select an installed interpreter.
    5. Prepare Python 3.11+ and ANTLR 4.13.2. Archive src/ from runtimeManifest.json's pinned sourceRevision into an ignored directory and generate its parser there. Set KAFE_REFERENCE_RUNTIME_ROOT to that directory. From the repository root run uv run --locked --group dev python kafe-vscode/scripts/verify-tutor-references.py and uv run --locked --group dev python kafe-vscode/scripts/verify-library-references.py. Each verifier checks the actual pinned source; reviewed fixtures run in disposable copies, with declared local assets staged for isolated cases. Use uv run --locked --group dev pytest tests/ -q for broader checkout regression evidence.
    6. Package locally and inspect the VSIX. It must contain generated library/reference data, their loaders, the shared corpus/search helpers, corpus definition and fixture license. Runtime assets remain separately published. Packaging, installing, publishing and observing hosted CI require their own evidence.

    Run native/package checks from kafe-vscode using existing installed tools:

    node test/run-extension-host-tests.js
node --test test/native/host-policy.test.cjs
node test/native/acceptance.cjs <absolute-ignored-evidence-directory>
node node_modules/@vscode/vsce/vsce package --out <absolute-ignored-output.vsix>
node test/verify-vsix.js <same-absolute-output.vsix>

    Native checks require the exact cached VS Code 1.96.0 host and isolated trusted/restricted profiles. They do not download it locally. Provisioning is restricted to genuine GitHub CI; do not spoof that environment, bypass provisioning or substitute the installed regular editor. If the cache is absent, record local native checks as unavailable; use a completed exact-revision hosted receipt when one exists, or the existing hosted workflow after separate push/dispatch authorization. Package inspection does not authorize installation or publication. npm ci has the documented upstream Mocha/glob deprecation exception; audits remain complete and blocking, with the unused signing-helper install script denied.

    Reference verification requires full token consumption without parser/lexer diagnostics, warnings treated as errors, exact exit codes and both complete output streams. This catches the parser's ability to stop before an unexpected trailing else. Controlled fundamentals also exercise input, conditional chains, built-in output, user-defined print and explicit invocation. Library verification joins successful token-observed top-level calls to the intended inventory, with unavailable paths retaining negative evidence. Zero exit alone is never a passing check. Parsing and execution each have a 15-second timeout. Disposable copies avoid mutating the checkout; they are not a security sandbox for arbitrary code. Run only reviewed repository fixtures in this development/CI gate, never silently in a learner project.

    The extension workflow watches extension, interpreter, test, documentation and lock/configuration inputs. It checks freshness and API evidence against the pinned interpreter, alongside unit/host/package and rendered-layout gates. Workflow configuration is not evidence of a hosted CI pass; read the result at the actual pushed commit.

    The unit matrix requires Ubuntu, Windows and macOS 26 on the standard Intel runner. Repeated hosted ARM capacity failures motivated the explicit Mac host selection; setup logs the OS and asserts actual Darwin/x64 execution. All tests and the native Windows prerequisite remain blocking. Passing Intel checks does not establish Apple Silicon host acceptance, which remains deferred capacity coverage.

    Model evaluation and limits¶

    Eight reviewed conceptual topics are bundled with the API contracts. They cover sensitivity, classifier error costs, imbalance, held-out evaluation, prediction thresholds, nonlinear representation, learning rate and overfitting. Concept-only questions receive the relevant explanation without incidental API catalogues or fixture fallback; explicit code requests retain related reviewed contracts and complete linked examples, and exact API queries retain their contract precedence. Topic/source changes invalidate generated freshness. See Evaluation alignment for practical scaffolding, Run evidence, consent and current research procedures with their limits.

    The Tutor should explain the requested concept first and use reference grounding quietly. Finding a fixture is not a learner achievement, and a default-only example does not establish that constructor options are unavailable. Reviewed contracts supply the complete positional forms. A decision-tree regression prompt preserves the reported Spanish question and checks the actual constructor options separately from the quality of a model's explanation.

    kafe-vscode/test/evals/kafe-code.json contains general-language prompts and review criteria for real-provider evaluation. The generated library-api.json beside it adds bilingual coverage of every intended top-level library call, known limits, unknown APIs, execution boundaries and the reported decision-tree teaching regression. Repeat them when the language, model, teaching instructions, or retrieval changes. Include new capabilities and discovered mistakes. Compare answers against expected behavior, not only the presence of instruction text. Provider evaluations require a configured authorized provider; the deterministic tests do not contact DeepSeek.

    Reference completeness means the intended shipped API has truthful contracts and evidence. It does not establish correctness of every model explanation, arbitrary architecture combination, learned model, proposed program or experimental backend path. Real-provider review should include English/Spanish API questions, exact member names, shape/precondition failures, unsupported bindings and requests with no executable runtime. Source provenance and zero exit are not correctness claims.

    The Tutor should use show(...) for ordinary built-in output and explicitly invoke a driver function when a complete program defines one. Top-level snippets do not require a main wrapper. A user-defined print remains valid. Missing library documentation must remain an explicit uncertainty rather than a guessed API. Syntax parsing alone cannot prove those semantic or behavioral properties.

    TeachingPolicy.js defines one guided baseline (kafe-guided-7) and independent guided/paused mode. Concept and syntax questions receive direct explanations; meaningful decisions invite one focused learner contribution without duplicate checkpoints. Bounded arithmetic and organization of supplied evidence are permitted while the learner retains the complete assessed submission and final individual conclusion. Feedback affirms supported reasoning and identifies at most one actual gap if present; a sound draft needs no forced revision. Aim for one manageable next step and at most one independent question when needed; there is no mandatory closing question or universal word cap. Brevity/detail requests affect presentation within eligible bounded history, not authority, accuracy or required reasoning. There is no durable style-memory field, Remember action, classifier or hidden preset. Compare actual provider responses against this common contract in English and Spanish; deterministic instruction checks do not establish provider compliance.

    Rendered layout regression¶

    The layout suite runs the shipped HTML, CSS, and browser scripts with synthetic conversation state. It checks document overflow, conversation reachability, fixed composer placement, and accessible speaker headings at narrow, short, and enlarged-text sizes.

    Run npm run test:layout with an installed Playwright. KAFE_PLAYWRIGHT_MODULE can name an existing installation and KAFE_LAYOUT_BROWSER an existing Chromium/Edge executable. The local test never downloads a browser. CI installs the pinned Playwright JavaScript tooling and uses the hosted Ubuntu image's preinstalled Chrome, logging its actual version. Missing Chrome fails setup; no layout assertion is skipped. This avoids apt/browser downloads that can exhaust the job before rendering begins. The browser version follows the runner image rather than a Playwright browser-build pin. This browser evidence is separate from native VS Code, physical IME, and screen-reader acceptance.

    Diagnosing a Tutor failure¶

    After changing the development extension, restart its Extension Development Host or use Developer: Reload Window there. Reproduce the failed message once, then open View: Toggle Output and select KAFE Tutor Diagnostics. The channel is created when the first traced event occurs; it contains only fixed metadata categories and numbers. Messages, tool arguments, source text, paths, credentials, raw exception messages and stacks are excluded. The recent buffer is bounded to 256 records and clears with a trace-reset marker when full.

    For a tool failure, inspect tool-start, tool-failed and turn-settled for the same local attempt number. reason distinguishes rejected arguments, invalid queries, missing captured sources and other validation categories. Known exception categories/codes are recorded; unclassified means the cause was not identified. turn-settled reports controller status and whether it remains busy. view-posted records VS Code's postMessage acceptance at a display revision; delivered: true does not prove the browser rendered it. The diagnostics never retry, resend or weaken a tool guard. They describe a reproduced attempt, not the cause of an older screenshot.

    Persistence, context and internal ownership¶

    Archive payload v2 stores only mode at the historical kafeTutor.conversations.v1 key. Strict original v1 validation precedes transformation and full v2 validation. The original archive remains until successful serialized save; a failed write retains live retry/export recovery. After v2 save, v1-only readers are unsupported. No backup key or dual write exists; public export remains schema 1. Migration preserves content, identities, dates, selection and drafts, but cannot recover previously filtered-away model text.

    The provider still receives at most eight eligible whole pairs / 32 KiB, while the full saved transcript remains readable/exportable. The context notice derives from the immutable captured submission's omissions, rather than a pre-send estimate; repeated identical conditions do not append transcript messages. Restoring clears optional source selections and executable authority. Source snapshots remain 64 KiB each, private Run output 1 MiB, and the archive retains its 200-chat / 10,000-entry / 5,000-pair / 4-MiB-content / 16-MiB-total limits. Export is independently bounded to 16 MiB. See the learner limits for other existing bounds.

    Private mutation signatures trigger persistence bookkeeping; they are not authorization. Events share a detached, deeply frozen display projection; explicit snapshots/captures remain independently detached. Full persistence capture/normalization moves to debounced save and explicit list/export/switch/disposal boundaries, with complete store validation preserved. The controlled profile in the engineering benchmark records measures synchronous notifications and an in-memory storage adapter, not network latency, native rendering or real disk writes.

    SessionCoordinator owns domain dependency enumeration and source/authorization revocation. The adapter retains native observation, real URI/filesystem authorization and freshness revisions, including rechecks after awaits. Its pure relevance query and source-change callback use the same native-active observation. The broader dependency union is metadata only: historical files do not gain admission or broaden ordinary edit relevance. ConversationSession.runTargetUris() reads the existing current-generation Run registry without creating another registry or restoring historical capabilities. Callback generation/disposal checks prevent an old event from mutating a newly selected conversation.
