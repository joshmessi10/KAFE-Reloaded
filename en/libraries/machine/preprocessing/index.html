    MACHINE: preprocessing and reduction¶

    Before teaching a model, you almost always need to prepare the data: put it on the same scale, fill gaps, turn words into numbers or keep only the useful columns. The tools on this page don't predict anything: they transform the data so models learn better.

    Tool What it does
    StandardScaler Centres each column on 0 and measures it in "deviations".
    MinMaxScaler Stretches each column between 0 and 1.
    RobustScaler Scales without being fooled by odd values.
    SimpleImputer Fills in missing data.
    LabelEncoder Swaps text labels for numbers.
    OneHotEncoder Opens a column of 0s and 1s per category.
    OrdinalEncoder Swaps a column's categories for numbers.
    PCA Summarises many columns in a few while losing almost nothing.
    LinearDiscriminantAnalysis Summarises columns so the groups stay apart.
    PolynomialFeatures Adds columns such as \(x^2\) to draw curves.
    VarianceThreshold Removes columns that barely change.
    RecursiveFeatureElimination Removes, one by one, the columns that help least.
    Tokenizer Turns text into lists of numbers.

    Before you start: fit, transform and fit_transform

    Every tool follows the same recipe:

    • fit(X) looks at the data and learns what it needs (averages, minimums, categories…).
    • transform(X) applies what it learned, to that data or to new data.
    • fit_transform(X) does both at once.
    • Many have inverse_transform, which undoes the transformation.

    Learn (fit) only from the training data and apply (transform) those same numbers to the test data. Otherwise the model "peeks" at the exam. Pipeline does this for you.

    StandardScaler: centre and measure in deviations¶

    The idea in one sentence¶

    StandardScaler subtracts each column's average and divides by its standard deviation. Each column ends up centred on 0, and a value of 1 means "one deviation above normal".

    An everyday comparison¶

    You got 15 out of 20 in one exam and 70 out of 100 in another. Which was better? It depends on how everyone else did. If the first exam's average was 10 and almost everyone scored between 7 and 13, your 15 is excellent. Standardising means comparing against the group's average.

    Your first StandardScaler¶

    import machine;
import math;

List[List[FLOAT]] pets = [[7.0, 1.0], [9.0, 3.0], [9.0, 5.0], [15.0, 7.0]];

MACHINE scaler = machine.standard_scaler();
List[List[FLOAT]] z = scaler.fit_transform(pets);
show(scaler.mean_);
show(math.round(scaler.scale_[0], 2));
show(math.round(scaler.scale_[1], 2));
for (i in range(0, len(z))):
    List[FLOAT] row = [math.round(z[i][0], 2), math.round(z[i][1], 2)];
    show(row);
;
List[List[FLOAT]] back = scaler.inverse_transform(z);
show(back[3]);

    [10.0, 4.0]
3.0
2.24
[-1.0, -1.34]
[-0.33, -0.45]
[-0.33, 0.45]
[1.67, 1.34]
[15.0, 7.0]

    What happened here?

    1. mean_ stores each column's average: 10.0 and 4.0.
    2. scale_ stores the deviation: 3.0 and 2.24.
    3. The first pet weighs 7: (7 − 10) ÷ 3 = -1.0.
    4. inverse_transform undoes everything: back to [15.0, 7.0].

    The maths with small numbers¶

    \[z = \frac{x - \text{average}}{\text{deviation}}\]
    import math;

List[FLOAT] weight = [7.0, 9.0, 9.0, 15.0];

FLOAT mean = 0.0;
for (i in range(0, len(weight))):
    mean = mean + weight[i] / len(weight);
;
show(mean);

FLOAT variance = 0.0;
for (i in range(0, len(weight))):
    variance = variance + (weight[i] - mean) * (weight[i] - mean) / len(weight);
;
show(variance);

FLOAT std = math.sqrt(variance);
show(std);

for (i in range(0, len(weight))):
    show(math.round((weight[i] - mean) / std, 2));
;

    10.0
9.0
3.0
-1.0
-0.33
-0.33
1.67

    The variance (9.0) is the average of the squared distances to the average. The deviation is its square root: 3.0.

    Call What it does
    machine.standard_scaler() Creates the tool.
    fit / transform / fit_transform / inverse_transform Learn, apply and undo.
    mean_ / scale_ Each column's average and deviation.
    Common mistake: transforming before learning 
    import machine;

MACHINE scaler = machine.standard_scaler();
show(scaler.transform([[1.0, 2.0]]));

    Exception: scaler: StandardScaler: Must call fit before transform

    When to use it?

    With models that measure distances or take gradient steps: KNN, SVM, K-Means, logistic regression and PCA. Trees don't care about scale.

    MinMaxScaler: everything between 0 and 1¶

    The idea in one sentence¶

    MinMaxScaler stretches each column so its smallest value is 0 and its largest is 1.

    An everyday comparison¶

    It's like turning scores from different exams into percentages: the group's worst result becomes 0 % and the best 100 %.

    import machine;

List[List[FLOAT]] pets = [[7.0, 1.0], [9.0, 3.0], [9.0, 5.0], [15.0, 9.0]];

MACHINE scaler = machine.minmax_scaler();
List[List[FLOAT]] scaled = scaler.fit_transform(pets);
show(scaler.data_min_);
show(scaler.data_max_);
show(scaler.scale_);
for (i in range(0, len(scaled))):
    show(scaled[i]);
;
show(scaler.transform([[11.0, 7.0]]));
show(scaler.inverse_transform([[0.5, 0.5]]));

    [7.0, 1.0]
[15.0, 9.0]
[0.125, 0.125]
[0.0, 0.0]
[0.25, 0.25]
[0.25, 0.5]
[1.0, 1.0]
[[0.5, 0.75]]
[[11.0, 5.0]]

    What happened here?

    The formula is \(x' = \dfrac{x - \text{min}}{\text{max} - \text{min}}\). For 9 kg: (9 − 7) ÷ (15 − 7) = 0.25. scale_ is \(1 \div (\text{max} - \text{min})\) = 0.125. A new value of 11 kg lands on 0.5.

    Call What it does
    machine.minmax_scaler() Creates the tool.
    fit / transform / fit_transform / inverse_transform Learn, apply and undo.
    data_min_ / data_max_ / scale_ Each column's minimum, maximum and scale.
    Common mistake: changing the number of columns 
    import machine;

MACHINE scaler = machine.minmax_scaler();
scaler.fit([[7.0, 1.0], [15.0, 9.0]]);
show(scaler.transform([[11.0]]));

    Exception: scaler: MinMaxScaler: Input dimension does not match fitted model

    RobustScaler: proof against odd values¶

    The idea in one sentence¶

    RobustScaler uses the median (the middle value) instead of the average, and the interquartile range (the width of the middle half of the data) instead of the deviation. That way one very odd value doesn't ruin everyone else's scale.

    An everyday comparison¶

    In a neighbourhood, nine houses are worth about 100 and one mansion is worth 10 000. The average says a "typical" house is worth 1 090, which describes nobody. The median says 100.

    import machine;
import math;

List[List[FLOAT]] coins = [[1.0], [2.0], [3.0], [4.0], [100.0]];

MACHINE robust = machine.robust_scaler();
List[List[FLOAT]] r = robust.fit_transform(coins);
show(robust.center_);
show(robust.scale_);
for (i in range(0, len(r))):
    show(r[i][0]);
;

MACHINE standard = machine.standard_scaler();
List[List[FLOAT]] s = standard.fit_transform(coins);
for (i in range(0, len(s))):
    show(math.round(s[i][0], 2));
;

    [3.0]
[2.0]
-1.0
-0.5
0.0
0.5
48.5
-0.54
-0.51
-0.49
-0.46
2.0

    What happened here?

    The median of 1, 2, 3, 4, 100 is 3 (center_). The 25th percentile is 2 and the 75th is 4, so the interquartile range is 2 (scale_). The formula is \((x - \text{median}) \div \text{IQR}\): the coin of 1 lands on (1 − 3) ÷ 2 = -1.0.

    Settings¶

    import machine;

List[List[FLOAT]] coins = [[1.0], [2.0], [3.0], [4.0], [100.0]];

MACHINE center_only = machine.robust_scaler(1, 0);
show(center_only.fit_transform(coins));
show(center_only.with_scaling);

MACHINE wide = machine.robust_scaler(1, 1, 0);
wide.fit(coins);
show(wide.scale_);
show(wide.inverse_transform([[0.0], [1.0]]));

    [[-2.0], [-1.0], [0.0], [1.0], [97.0]]
False
[3.0]
[[3.0], [6.0]]
    • machine.robust_scaler(1, 0) only centres (subtracts the median) and doesn't scale.
    • machine.robust_scaler(1, 1, 0) uses the range from the 0th to the 75th percentile: from 1 to 4, width 3.0.
    Call What it does
    machine.robust_scaler(with_centering, with_scaling, quantile_low, quantile_high) All optional INTs: 1/0 to centre and scale, and the range percentiles (default 25 and 75).
    fit / transform / fit_transform / inverse_transform Learn, apply and undo.
    center_ / scale_ Each column's median and range.
    Common mistake: percentiles with decimals

    In KAFE the percentiles are written as integers:

    import machine;

MACHINE robust = machine.robust_scaler(1, 1, 10.0);

    Exception: machine: Function robust_scaler expects argument of type INT, got type FLOAT

    SimpleImputer: fill the gaps¶

    The idea in one sentence¶

    When a value is missing (math.nan), SimpleImputer fills it with a typical value from its column: the average, the median, the most frequent value or a fixed number.

    An everyday comparison¶

    If a thermometer failed one day, you don't throw away the whole week: you write down that week's typical temperature for that day.

    import machine;
import math;

List[List[FLOAT]] days = [[20.0, 4.0], [22.0, math.nan], [math.nan, 6.0], [24.0, 14.0]];

MACHINE imputer = machine.simple_imputer("mean");
List[List[FLOAT]] full = imputer.fit_transform(days);
show(imputer.strategy);
show(imputer.statistics_);
for (i in range(0, len(full))):
    show(full[i]);
;

MACHINE middle = machine.simple_imputer("median");
middle.fit(days);
show(middle.statistics_);

    mean
[22.0, 8.0]
[20.0, 4.0]
[22.0, 8.0]
[22.0, 6.0]
[24.0, 14.0]
[22.0, 6.0]

    What happened here?

    1. With "mean", the first column's average without the gap is (20 + 22 + 24) ÷ 3 = 22, and the second's is (4 + 6 + 14) ÷ 3 = 8.
    2. With "median", the second column gives 6: the median isn't dragged by the 14.

    For text, use "most_frequent", the value that repeats most:

    import machine;
import pardos;

PARDOS pets = pardos.DataFrame(["pet", "color"], [["cat", "black"], ["dog", "white"], ["cat", "black"], ["cat", "brown"]]);

MACHINE imputer = machine.simple_imputer("most_frequent");
imputer.fit(pets);
show(imputer.statistics_);

    ['cat', 'black']

    And to fill with a fixed number there's a separate function:

    import machine;
import math;

List[List[FLOAT]] days = [[20.0, 4.0], [22.0, math.nan], [math.nan, 6.0]];

MACHINE imputer = machine.simple_imputer_constant(0.0);
show(imputer.fit_transform(days));
show(imputer.fill_value);

    [[20.0, 4.0], [22.0, 0.0], [0.0, 6.0]]
0.0
    Call What it does
    machine.simple_imputer(strategy) strategy: "mean", "median" or "most_frequent".
    machine.simple_imputer_constant(fill_value) Always fills with fill_value.
    fit / transform / fit_transform Learn and fill.
    statistics_ / strategy / fill_value Each column's fill value and the settings.
    Common mistake: asking simple_imputer for \"constant\" 
    import machine;

MACHINE imputer = machine.simple_imputer("constant");

    Exception: machine: simple_imputer: use machine.simple_imputer_constant(fill_value) for constant strategy

    LabelEncoder: words to numbers¶

    The idea in one sentence¶

    Models only understand numbers. LabelEncoder sorts the labels alphabetically and gives each one a number: 0, 1, 2…

    An everyday comparison¶

    It's a class register: instead of "Ana", "Ben", "Carla", the teacher says "number 0, number 1, number 2".

    import machine;

List[STR] fruits = ["pear", "apple", "pear", "kiwi"];

MACHINE encoder = machine.label_encoder();
List[INT] codes = encoder.fit_transform(fruits);
show(encoder.classes_);
show(codes);
show(encoder.transform(["kiwi", "kiwi"]));
show(encoder.inverse_transform([0, 2]));

    ['apple', 'kiwi', 'pear']
[2, 0, 2, 1]
[1, 1]
['apple', 'pear']
    Call What it does
    machine.label_encoder() Creates the tool. It works with a list of labels (List[STR]).
    fit / transform / fit_transform / inverse_transform Learn, encode and decode.
    classes_ The labels in order: the position is their number.
    Common mistake: a label it never saw 
    import machine;

MACHINE encoder = machine.label_encoder();
encoder.fit(["pear", "apple", "kiwi"]);
show(encoder.transform(["mango"]));

    Exception: encoder: LabelEncoder: Unseen label 'mango'

    Use it for y, not for X

    If you turn "red, green, blue" into 0, 1, 2 inside X, the model will think blue is "twice" green. For data columns, use OneHotEncoder.

    OneHotEncoder: one column per category¶

    The idea in one sentence¶

    OneHotEncoder replaces a column of categories with one column per category, with a 1 where it applies and 0 in the rest. That way no category looks "bigger" than another.

    An everyday comparison¶

    On a form, instead of writing your pet, you tick a box: ☑ cat ☐ dog ☐ fish.

    It works with PARDOS tables and you tell it which columns to convert:

    import machine;
import pardos;

PARDOS pets = pardos.DataFrame(["name", "pet"], [["Luna", "cat"], ["Max", "dog"], ["Nemo", "fish"], ["Tom", "cat"]]);

MACHINE encoder = machine.one_hot_encoder();
PARDOS wide = encoder.fit_transform(pets, ["pet"]);
show(wide);
show(encoder.columns_);
show(encoder.handle_unknown);
show(encoder.inverse_transform(wide));

    "cols: ['name', 'pet_cat', 'pet_dog', 'pet_fish'], rows: [['Luna', 1, 0, 0], ['Max', 0, 1, 0], ['Nemo', 0, 0, 1], ['Tom', 1, 0, 0]]"
['pet']
error
"cols: ['name', 'pet'], rows: [['Luna', 'cat'], ['Max', 'dog'], ['Nemo', 'fish'], ['Tom', 'cat']]"
    Call What it does
    machine.one_hot_encoder() Creates the tool.
    fit(df, columns) / fit_transform(df, columns) Learns the categories of those columns (and converts them).
    transform(df) / inverse_transform(df) Convert and undo.
    columns_ / handle_unknown The converted columns and what to do with new categories ("error").
    Common mistake: a category it never saw 
    import machine;
import pardos;

PARDOS pets = pardos.DataFrame(["pet"], [["cat"], ["dog"]]);
PARDOS other = pardos.DataFrame(["pet"], [["bird"]]);

MACHINE encoder = machine.one_hot_encoder();
encoder.fit(pets, ["pet"]);
show(encoder.transform(other));

    Exception: encoder: OneHotEncoder: Unseen category 'bird' in column 'pet'. Use handle_unknown='ignore' to ignore unknown categories.

    OrdinalEncoder: categories to numbers, in a table¶

    The idea in one sentence¶

    OrdinalEncoder does the same as LabelEncoder, but on columns of a table: it swaps each category for its position in alphabetical order.

    import machine;
import pardos;

PARDOS shirts = pardos.DataFrame(["color", "size"], [["red", "small"], ["blue", "large"], ["red", "medium"], ["green", "small"]]);

MACHINE encoder = machine.ordinal_encoder();
PARDOS coded = encoder.fit_transform(shirts, ["size"]);
show(coded);
show(encoder.columns_);
show(encoder.inverse_transform(coded));

    "cols: ['color', 'size'], rows: [['red', 2], ['blue', 0], ['red', 1], ['green', 2]]"
['size']
"cols: ['color', 'size'], rows: [['red', 'small'], ['blue', 'large'], ['red', 'medium'], ['green', 'small']]"

    Alphabetical order, not size order

    The sizes became large = 0, medium = 1, small = 2: alphabetical, not small to large. If the order matters to your model, check that the alphabetical one makes sense, or use OneHotEncoder.

    Call What it does
    machine.ordinal_encoder() Creates the tool.
    fit(df, columns) / fit_transform(df, columns) / transform / inverse_transform Same as OneHotEncoder.
    columns_ The converted columns.
    Common mistake: a column that doesn't exist 
    import machine;
import pardos;

PARDOS shirts = pardos.DataFrame(["size"], [["small"], ["large"]]);

MACHINE encoder = machine.ordinal_encoder();
encoder.fit(shirts, ["color"]);

    Exception: encoder: OrdinalEncoder: Column 'color' not found in DataFrame

    PCA: the best shadow¶

    The idea in one sentence¶

    PCA (Principal Component Analysis) finds the direction in which the data is most spread out and projects it onto that direction. That way it summarises many columns in a few, losing as little as possible.

    An everyday comparison¶

    If you shine a torch at a pencil, its shadow can be a dot (lit end-on) or a long line (lit from the side). PCA looks for the angle with the longest shadow: the one that keeps the most information.

    Your first PCA¶

    import machine;
import math;

List[List[FLOAT]] points = [[1.0, 1.0], [2.0, 3.0], [3.0, 2.0], [4.0, 4.0]];

MACHINE pca = machine.pca(1);
List[List[FLOAT]] shadow = pca.fit_transform(points);
pca.round(3);
show(pca.mean_);
show(pca.explained_variance_);
show(pca.components_);
for (i in range(0, len(shadow))):
    show(math.round(shadow[i][0], 2));
;
List[List[FLOAT]] back = pca.inverse_transform(shadow);
for (i in range(0, len(back))):
    List[FLOAT] row = [math.round(back[i][0], 2), math.round(back[i][1], 2)];
    show(row);
;

    [2.5, 2.5]
[3.0]
[[0.707, 0.707]]
-2.12
0.0
0.0
2.12
[1.0, 1.0]
[2.5, 2.5]
[2.5, 2.5]
[4.0, 4.0]

    What happened here?

    1. machine.pca(1) summarises 2 columns in 1.
    2. components_ is the direction: [0.707, 0.707], the diagonal.
    3. explained_variance_ (3.0) says how much spread there is in that direction.
    4. The shadows are -2.12, 0.0, 0.0 and 2.12.
    5. inverse_transform goes back to 2 columns, but only recovers what was in the shadow: points (2, 3) and (3, 2) both end up at (2.5, 2.5). That's the information that's lost.

    The maths with small numbers¶

    PCA looks at the covariance matrix: how much each column varies and how much they vary together.

    import math;

List[FLOAT] x = [1.0, 2.0, 3.0, 4.0];
List[FLOAT] y = [1.0, 3.0, 2.0, 4.0];
INT n = len(x);

FLOAT mx = 0.0;
FLOAT my = 0.0;
for (i in range(0, n)):
    mx = mx + x[i] / n;
    my = my + y[i] / n;
;

FLOAT vx = 0.0;
FLOAT vy = 0.0;
FLOAT cxy = 0.0;
for (i in range(0, n)):
    vx = vx + (x[i] - mx) * (x[i] - mx) / (n - 1);
    vy = vy + (y[i] - my) * (y[i] - my) / (n - 1);
    cxy = cxy + (x[i] - mx) * (y[i] - my) / (n - 1);
;
show(math.round(vx, 3));
show(math.round(vy, 3));
show(math.round(cxy, 3));

FLOAT half = (vx + vy) / 2;
FLOAT gap = math.sqrt((vx - vy) * (vx - vy) / 4 + cxy * cxy);
show(math.round(half + gap, 3));
show(math.round(half - gap, 3));

FLOAT d = math.sqrt(0.5);
for (i in range(0, n)):
    show(math.round((x[i] - mx) * d + (y[i] - my) * d, 2));
;

    1. The two columns' variances are 1.667 and their covariance is 1.333: they grow together.
    2. A 2 × 2 matrix has a direct formula for its eigenvalues: 3.0 (the diagonal direction) and 0.333 (the perpendicular one). The large one is what PCA keeps.
    3. The shadows are each point (minus the average) times the direction \((\sqrt{0.5}, \sqrt{0.5})\).
    For the curious 🤓

    With \(X\) centred, the covariance is \(C = \frac{1}{n-1}X^T X\). The principal components are the eigenvectors of \(C\) sorted by their eigenvalue \(\lambda\); each \(\lambda\) is the variance in that direction. Keeping \(k\) components keeps the fraction \(\sum_{i \le k}\lambda_i \big/ \sum_i \lambda_i\) of the total variance: here \(3 \div 3.333 = 90\%\).

    Common mistake: asking for more components than columns

    LinearDiscriminantAnalysis: separate while summarising¶

    The idea in one sentence¶

    LDA also summarises columns by projecting, but it knows the groups and picks the direction in which the groups are farthest apart from each other and tightest inside. It can also classify.

    An everyday comparison¶

    To photograph two football teams, PCA looks for the angle where you see the most people; LDA looks for the angle where the shirts don't mix.

    import machine;
import math;

List[List[FLOAT]] pets = [[1.0, 2.0], [2.0, 1.0], [3.0, 3.0], [6.0, 5.0], [8.0, 7.0], [7.0, 6.0]];
List[INT] kind = [0, 0, 0, 1, 1, 1];

MACHINE lda = machine.linear_discriminant_analysis();
lda.fit(pets, kind);
show(lda.n_components);
show(lda.classes_);
show(lda.prior_);
show(lda.means_);
show(lda.predict([[3.0, 3.0], [7.0, 6.0]]));
show(lda.score(pets, kind));

List[List[FLOAT]] line = lda.transform(pets);
for (i in range(0, len(line))):
    show(math.round(line[i][0], 2));
;

    1. With 2 groups, LDA keeps 1 direction: n_components is 1.
    2. prior_ and means_ are each group's share and centre.
    3. predict puts [3, 3] in group 0 and [7, 6] in group 1. The accuracy is 1.0.
    4. transform gives each pet's shadow: cats land between 1.7 and 3.93 and dogs between 7.47 and 10.09, without mixing.
    For the curious 🤓

    LDA maximises Fisher's ratio: the distance between the group centres over the spread within each group. With two groups, the best direction is \(w \propto S_W^{-1}(\mu_1 - \mu_0)\), where \(S_W\) adds up each group's spread. With \(k\) groups you can get at most \(k - 1\) directions.

    Common mistake: a single group

    PolynomialFeatures: curves with a straight-line model¶

    The idea in one sentence¶

    PolynomialFeatures adds new columns built from the ones you have: squares (\(x^2\)), products (\(x \cdot y\))… With them, a linear model can draw curves.

    An everyday comparison¶

    A square's area doesn't grow in a straight line with its side: side 2 gives area 4, side 3 gives area 9. A straight ruler can't follow those points. But if you give the model the column "side²", the relationship is straight again: area = 1 × side².

    import machine;

List[List[FLOAT]] side = [[1.0], [2.0], [3.0], [4.0]];
List[FLOAT] area = [1.0, 4.0, 9.0, 16.0];

MACHINE poly = machine.polynomial_features(2, False);
List[List[FLOAT]] wide = poly.fit_transform(side);
show(wide);

MACHINE model = machine.linear_regression();
model.fit(wide, area);
show(model.predict(poly.transform([[5.0]])));

    [[1.0, 1.0], [2.0, 4.0], [3.0, 9.0], [4.0, 16.0]]
[25.0]

    Linear regression predicted 25.0 for side 5: exactly 5². With two columns and degree 2, every combination appears:

    import machine;

MACHINE poly = machine.polynomial_features(2);
show(poly.fit_transform([[2.0, 3.0]]));
show(poly.degree);
show(poly.include_bias);
show(poly.n_features_in_);
show(poly.n_features_out_);

    For [2, 3] you get 6 columns: 1 (the bias), 3, 9 (3²), 2, 6 (2 × 3) and 4 (2²).

    Careful with the degree

    The columns grow very fast: with 10 columns and degree 3 you get 286. With a high degree, the model can memorise the data.

    VarianceThreshold: out with what doesn't change¶

    The idea in one sentence¶

    A column that always has the same value doesn't help tell anything apart. VarianceThreshold removes the columns whose variance doesn't exceed a threshold.

    An everyday comparison¶

    If everyone in a survey answered "yes" to a question, that question can't help you separate anyone.

    import machine;

List[List[FLOAT]] students = [[1.0, 6.0, 10.0], [1.0, 6.5, 14.0], [1.0, 7.0, 12.0], [1.0, 6.5, 16.0]];

MACHINE filter = machine.variance_threshold();
List[List[FLOAT]] kept = filter.fit_transform(students);
show(filter.variances_);
show(filter.selected_indices_);
show(kept[0]);

MACHINE strict = machine.variance_threshold(0.5);
strict.fit(students);
show(strict.threshold);
show(strict.selected_indices_);
show(strict.n_features_in_);
show(strict.n_features_out_);

[1, 2]
[6.0, 10.0]
0.5

    What happened here?

    The variances are 0.0, 0.125 and 5.0. With the default threshold (0.0) the first column goes and positions [1, 2] remain. With 0.5 the second goes too and only [2] remains.

    RecursiveFeatureElimination: remove what helps least¶

    The idea in one sentence¶

    RFE trains a linear regression, looks at which column has the smallest weight, removes it and trains again, until the number of columns you asked for remains.

    An everyday comparison¶

    A coach wants a team of 2. They watch all 3 play, drop the one who contributed least, and if there are still too many, watch them play again.

    import machine;

List[List[FLOAT]] houses = [[1.0, 5.0, 2.0], [2.0, 3.0, 1.0], [3.0, 8.0, 4.0], [4.0, 1.0, 3.0], [5.0, 6.0, 6.0]];
List[FLOAT] price = [8.0, 7.0, 18.0, 17.0, 28.0];

MACHINE rfe = machine.recursive_feature_elimination(2);
rfe.fit(houses, price);
show(rfe.n_features);
show(rfe.n_features_in_);
show(rfe.ranking_);
show(rfe.support_);
show(rfe.selected_indices_);
show(rfe.transform(houses)[0]);

    2
3
[1, 3, 1]
[True, False, True]
[0, 2]
[1.0, 2.0]

    What happened here?

    These houses' price is exactly 2 × column 0 + 3 × column 2: column 1 is pure noise. RFE removed it: support_ is [True, False, True] and ranking_ is [1, 3, 1] (1 = kept).

    Call What it does
    machine.recursive_feature_elimination(n_features) n_features (INT, default 1): how many columns remain.
    fit(X, y) / transform(X) Choose columns (with the answers) and keep them.
    support_, ranking_, selected_indices_ Which columns remain, their elimination order and their positions.
    Common mistake: asking for more columns than there are 
    import machine;

    Exception: rfe: RecursiveFeatureElimination: n_features (4) > n_features_in (3)

    Weights depend on scale

    RFE compares weights. If one column is in metres and another in millimetres, their weights aren't comparable: scale first with StandardScaler.

    Tokenizer: text to numbers¶

    The idea in one sentence¶

    Tokenizer lowercases the text, splits it into words and gives each word a number according to how frequent it is. That way a sentence becomes a list of numbers that a model (for example, a GESHA network) can read.

    An everyday comparison¶

    It's a numbered dictionary: the most used word gets the smallest number. Instead of sending "the dog eats the bone", you send "2 5 3 2 6".

    import machine;

List[STR] notes = ["The cat eats", "the dog eats the bone"];

MACHINE tok = machine.tokenizer(0, "<?>");
show(tok.fit_transform(notes));
show(tok.transform(["the bird eats"]));
show(tok.vocabulary_size);
show(tok.num_words);
show(tok.oov_token);

MACHINE small = machine.tokenizer(2);
small.fit(notes);
show(small.transform(["the bird eats"]));
show(small.vocabulary_size);

    [[2, 4, 3], [2, 5, 3, 2, 6]]
[[2, 1, 3]]
7
0
<?>
[[1, 2]]
3

    What happened here?

    1. machine.tokenizer(0, "<?>"): no word limit (0) and "<?>" for unknown words, which takes number 1.
    2. "the" appears 3 times: it gets 2. "eats" appears twice: 3. Then come cat 4, dog 5 and bone 6.
    3. "bird" wasn't in the vocabulary: it becomes 1.
    4. vocabulary_size is 7: numbers 0 to 6.
    5. With machine.tokenizer(2) only the 2 most frequent words are kept, with no unknown-word marker: "the bird eats" becomes [1, 2] and "bird" disappears.
    Call What it does
    machine.tokenizer(num_words, oov_token) num_words (INT, 0 = no limit); oov_token (STR, empty by default): the marker for unknown words.

    vocabulary_size, num_words, oov_token The vocabulary size (counting 0) and the settings.

    What did you learn on this page?

    • Scalers put columns on a similar scale: StandardScaler (average and deviation), MinMaxScaler (0 to 1) and RobustScaler (median, proof against odd values).
    • SimpleImputer fills gaps; encoders turn categories into numbers.
    • PCA and LDA summarise columns by projecting; PolynomialFeatures adds columns to draw curves.
    • VarianceThreshold and RFE remove columns that don't help; Tokenizer turns text into numbers.
    • Learn with fit only on the training data and apply with transform everywhere else.
